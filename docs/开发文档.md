# EastBill 开发文档

## 系统结构

EastBill 使用单仓库管理多个独立进程。每个后端服务有自己的启动类、配置、数据库和初始化脚本，可分别开发、启动和部署。

```text
EastBill/
├─ vue-project/       Vue 3 管理界面和旅行展板
├─ springboot/        Maven 聚合目录
│  ├─ auth-service/   用户、验证码和 JWT，8081，MySQL
│  ├─ bill-service/   账单、分类和账户，8083，MySQL
│  ├─ travel-service/ 机票、列车和足迹，8084，PostgreSQL/PostGIS
│  └─ diary-service/  日记服务边界，8085，PostgreSQL
├─ mapserver/         FastAPI 地理服务，8765
├─ spyderserver/      12306 查询服务，8082
└─ docs/              项目文档
```

旅行服务通过 HTTP 调用 mapserver 和 spyderserver。服务间不共享 Java 代码或数据库连接。JWT 由 auth-service 签发，前端通过统一请求拦截器附带令牌。

## 独立启动

在 IDEA 中导入 `springboot/pom.xml`，每个服务使用自己的入口类运行：

| 服务 | 主类 | 端口 | 数据库 |
| --- | --- | ---: | --- |
| 用户 | `com.AuthServiceApplication` | 8081 | MySQL `eastbill_identity` |
| 账单 | `com.BillServiceApplication` | 8083 | MySQL `eastbill_bill` |
| 旅行 | `com.TravelServiceApplication` | 8084 | PostgreSQL `travel_database` |
| 日记 | `com.DiaryServiceApplication` | 8085 | PostgreSQL `diary_database` |

服务之间没有启动依赖。使用哪个功能，就只需启动对应服务和它依赖的基础设施。例如开发旅行功能时启动 PostgreSQL、travel-service、mapserver；需要车次在线查询时再启动 spyderserver。

各服务数据库首次创建或需要重置时，进入对应服务目录运行自己的脚本：

```powershell
cd springboot\auth-service
.\init-database.ps1

cd ..\bill-service
.\init-database.ps1

cd ..\travel-service
.\init-database.ps1

cd ..\diary-service
.\init-database.ps1
```

初始化脚本会删除并重建当前服务专属数据库。正常启动服务不需要重复初始化。MySQL 服务在启动时只创建缺少的表，不会清空已有记录。数据库凭据和服务地址可通过各模块 `application.yml` 中列出的环境变量覆盖。

## 前端

```powershell
cd vue-project
npm install
npm run dev
```

服务地址集中配置于 `vue-project/.env`：`VITE_AUTH_BASE_URL`、`VITE_BILL_BASE_URL`、`VITE_TRAVEL_BASE_URL`、`VITE_DIARY_BASE_URL` 和 `VITE_MAP_BASE_URL`。所有 Axios 实例复用 `src/utils/request.js` 中的拦截器。

## 旅行数据表格导入导出

各分类管理页只导出或导入当前分类：机票使用 `.xlsx`，足迹可导出 `.xlsx` 或 GeoPackage（`.gpkg`），铁路使用 GeoPackage，包含列车属性表、路线线图层和途经站点图层。足迹 GPKG 使用 WGS 84 点图层；没有坐标的记录仍保留在属性表中。各页可下载对应空模板，也可从单条记录的“导出”按钮生成只含该记录的文件。填一行/一条即可单条导入，多行/多条即批量导入。导入默认新增，也可选择“按ID更新”，需保留原记录 ID。左侧底部“导出全部数据”会下载 ZIP，包含机票 Excel、足迹 GeoPackage 和铁路 GeoPackage。

接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/travel/export` | 导出全库 ZIP |
| `GET` | `/travel/export?type=flight` | 导出全部机票 Excel；支持 `footprint` 和 `train` |
| `GET` | `/travel/export?type=footprint&format=gpkg` | 导出足迹 GeoPackage；默认格式仍为 Excel |
| `GET` | `/travel/export?type=train&id=1` | 导出单条铁路 GeoPackage；足迹单条导出可指定 `format=gpkg` |
| `DELETE` | `/travel/flights/batch`、`/travel/trains/batch`、`/travel/footprints/batch` | 请求体传 ID 数组，单次批量删除并返回实际删除数量 |
| `GET` | `/travel/export/template?type=train` | 下载对应分类模板；铁路模板为 GeoPackage |
| `POST` | `/travel/import?type=train&mode=append` | 导入铁路 GeoPackage；`type` 必填，`mode=update` 按 ID 更新 |

机票和足迹 Excel 各只包含本类数据表。铁路 GeoPackage 中 `train_records` 存行程属性，`train_routes` 是路线线图层，`train_waypoints` 是站点点图层；三者以 `train_id` 关联，QGIS 可直接加载空间图层和编辑属性。铁路里程未填写时优先按路线几何计算，路线不可用时按有坐标的途经站计算；已有里程值不会被自动覆盖，管理页仍可直接编辑。导入逐记录校验并返回成功数量和失败原因。

## 地理服务

```powershell
cd mapserver
.\.venv\Scripts\python.exe main.py
```

mapserver 使用 `mapserver/config/application.json` 配置数据路径；运行数据包括 `data/geo.sqlite`、`data/world.pmtiles`、`data/china.pmtiles` 和铁路网 GeoPackage。边界原始 GeoJSON 位于 `data/source/boundaries`。这些是业务数据资产，清理源码时不要一并删除。

```powershell
cd spyderserver
python main.py
```

## 初始化数据说明

- 业务数据库彼此独立，表结构和初始化脚本都归属相应服务。
- 当前账户库和旅行库已清空；首次使用先通过注册页面创建用户。
- 账单服务初始化少量基础分类和系统账户，不创建账单记录。
- 地图服务的数据不在业务数据库重建范围内。
- `db/springdatabase.db` 是旧版 SQLite 快照，仅作为历史归档；当前服务不会读取它。初始化以各服务目录的 `init-database.ps1` 和 `src/main/resources` 为准。
