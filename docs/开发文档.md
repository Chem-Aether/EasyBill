# EastBill 项目开发文档

## 1. 项目概述

EastBill 是一个个人使用的前后端分离综合管理系统，目前包含以下模块：

- 用户系统：注册、登录、验证码、密码找回和 JWT 登录状态。
- 账单管理：账户、收支记录、分类维护和统计图表。
- 旅行管理：火车票、机票、途经站、旅行统计和足迹展示。
- 离线地图：全球概览、中国街道级地图、已探索城市、航线和铁路轨迹。

系统采用 Vue 单页应用、Spring Boot REST API 和 MySQL 数据库。离线地图与地理检索由独立的 Python/FastAPI 服务提供。

## 5. 数据库初始化

创建数据库：

```sql
CREATE DATABASE springdatabase
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

按以下顺序导入 SQL：

1. `db/user/user.sql`
2. `db/bill/bill.sql`
3. `db/bill/bill_stat.sql`
4. `db/travel/travel.sql`

地理基础数据不导入 MySQL。机场、车站、行政区、边界和 POI 统一位于 `mapserver/data/geo.sqlite`。

主要数据表：

| 模块 | 表 |
| --- | --- |
| 用户 | `user` |
| 账单 | `account`、`bill_category`、`bill_record` |
| 旅行 | `flight`、`train`、`train_station`、`foot_spot` |
| 地理资源 | 独立 SQLite，不属于 MySQL 业务库 |

数据库连接配置位于 `springboot/src/main/resources/application.yml`。提交代码时不要保存生产密码或正式 JWT 密钥，推荐后续改为环境变量。

## 6. 启动项目

### 6.1 启动基础服务

确认 MySQL 已启动。如果验证码和会话功能依赖 Redis，再启动 Redis：

```powershell
redis-server
```

### 6.2 启动 Spring Boot

在 IDEA 中打开 `springboot`，运行：

```text
com.SpringbootApplication
```

启动成功后 API 监听 `8081`。

### 6.3 启动离线地图服务

```powershell
cd mapserver
.\run.ps1
```

地图服务监听 `127.0.0.1:8765`。PMTiles 必须通过支持 HTTP Range 的服务读取，不能直接使用 `file://` 打开。

验证地图服务：

```powershell
Invoke-WebRequest `
  -UseBasicParsing `
  http://127.0.0.1:8765/world.pmtiles `
  -Headers @{ Range = 'bytes=0-7' }
```

正常状态码为 `206 Partial Content`，不是错误。

### 6.4 启动 Vue 前端

```powershell
cd vue-project
npm install
npm run dev
```

访问 `http://localhost:5173`。开发命令包含 `vite --force`，用于避免 MapLibre Worker 被旧的 Vite 预构建缓存破坏。

## 7. 前端架构

### 7.1 路由

主路由通过 `import.meta.glob('../modules/**/router.js')` 自动聚合模块路由。

| 路径 | 页面 |
| --- | --- |
| `/login` | 登录 |
| `/register` | 注册 |
| `/forgot-password` | 找回密码 |
| `/home` | 系统模块入口 |
| `/bill/*` | 账单管理 |
| `/travel` | 旅行可视化大屏 |
| `/travel/admin/trainTicket` | 火车票管理 |
| `/travel/admin/flightTicket` | 机票管理 |

### 7.2 网络请求

`src/utils/request.js` 创建统一 Axios 实例：

- API 基地址：`http://127.0.0.1:8081`
- 超时：10 秒
- 自动读取 `localStorage.token` 并写入请求头 `token`
- 统一处理 401、403、404 和 500
- `fullResponse: true` 用于需要读取响应头的接口

后续部署时建议将 API 地址改为 `VITE_API_BASE_URL` 环境变量。

### 7.3 状态管理

- `TravelStore.js`：旅行地图模式，支持足迹、航线和铁路。
- `allAirportsList.js`：机场远程搜索状态。
- `allTrainStationsList.js`：车站远程搜索状态。

机场和车站不会在页面初始化时全量加载。用户输入搜索内容后，Element Plus Autocomplete 防抖调用后端 `/search`，每次最多返回 20 条，并使用请求序号避免旧响应覆盖新结果。

## 8. 后端架构

每个业务模块按以下结构组织：

```text
controller -> service -> mapper -> entity
```

- Controller：定义 REST 路由和参数。
- Service：业务逻辑、统计和批量资源关联。
- Mapper：MyBatis-Plus 数据访问。
- Entity/DTO：数据库实体与请求模型。
- `Result`：统一 API 返回结构。

## 9. 离线地图

### 9.1 数据组成

| 文件 | 范围 | 层级 | 用途 |
| --- | --- | --- | --- |
| `world.pmtiles` | 全球 | Z0-Z6 | 全球概览和跨国航线背景 |
| `china.pmtiles` | 中国 | Z0-Z14 | 中国街道、建筑和详细地理信息 |

地图由 `vue-project/src/modules/travel/views/Board/Map.vue` 渲染。

### 9.2 图层逻辑

- MapLibre 同时注册 `world` 和 `china` 两个矢量源。
- 全球图层始终作为基础背景。
- 中国图层从约 Z6.5 开始叠加，提供 Z14 细节。
- 道路采用暗色样式，保证足迹和线路覆盖层清晰。
- `visited-city-codes` 返回城市编码，前端向地图服务批量请求对应 GeoJSON 边界并点亮。
- `getTicketData` 批量补齐当前航班或车次的起终点坐标，前端据此生成 GeoJSON 线和节点。
- 地图不请求全部机场或全部车站。

### 9.3 地图服务

`mapserver/app/main.py`：

- 只允许访问 `world.pmtiles` 和 `china.pmtiles`。
- 支持 `Range` 请求和 `206 Partial Content`。
- 支持跨域访问。
- 不会把 6GB 中国数据一次性读入内存。
- 可通过 `MAP_PORT` 修改端口，默认 `8765`。

前端可通过环境变量覆盖地图服务地址：

```env
VITE_MAP_SERVER=http://127.0.0.1:8765
```

## 10. 旅行数据流程

### 足迹模式

```text
foot_spot.adcode
  -> FootSpotService 转换为城市编码
  -> /travel/visited-city-codes
  -> 地图服务批量输出城市 GeoJSON
  -> MapLibre 动态边界图层
  -> 点亮已探索城市
```

### 航线模式

```text
flight 记录中的 departure_icao / arrival_icao
  -> TicketStatisticsService 批量查询 airport
  -> 返回起终点经纬度
  -> MapLibre LineString + Point
```

### 铁路模式

```text
train 记录中的 start_station / end_station
  -> TicketStatisticsService 批量查询 train_stations
  -> 返回起终点经纬度
  -> MapLibre LineString + Point
```

## 11. 开发约定

### 足迹地区点亮

管理入口：`/travel/admin/footprint`。

新增足迹时搜索全国 POI 或直接地图选点。前端调用地图服务逆编码展示所属区县；Spring 保存前再次按经纬度逆编码，并以地图服务结果校正 `adcode`，不信任客户端提交的行政区。旅行大屏按城市编码动态获取边界，不再打包本地省市县 GeoJSON。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/travel/footprints` | 查询足迹管理列表（含行政区全名） |
| `POST` | `/travel/footprints` | 新增足迹 |
| `PUT` | `/travel/footprints/{id}` | 修改足迹 |
| `DELETE` | `/travel/footprints/{id}` | 删除足迹 |
| `GET` | `/travel/visited-city-codes` | 返回地图需要点亮的城市编码 |

足迹请求体示例：

```json
{
  "spotName": "西湖断桥",
  "spotType": "景点",
  "visitTime": "2026-09-19",
  "longitude": 120.1502,
  "latitude": 30.2591
}
```

经纬度是行政区识别的事实来源，`adcode` 由 Spring 调用地图服务生成和校正。新增、修改或删除后，重新进入旅行大屏即可加载最新点亮结果。

足迹表单支持完全离线的地图选点。选点地图读取 `world.pmtiles`、`china.pmtiles`，点击后由地图服务执行边界索引和精确点面判断。搜索使用 SQLite 全国 POI 索引，不受当前地图视野限制。旅行大屏会将坐标渲染为聚合点，并按需加载已探索城市边界。

已有数据库升级时执行一次：

```powershell
mysql -uroot -p springdatabase < db/travel/upgrade_foot_spot_coordinates.sql
```

升级增加以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `longitude` | `DECIMAL(10,7)` | WGS84 经度 |
| `latitude` | `DECIMAL(10,7)` | WGS84 纬度 |
| `address` | `VARCHAR(255)` | 街道、门牌号或位置说明 |

历史足迹允许暂时没有坐标，会在列表中显示“未选点”；编辑并选点后即可在大屏显示具体标记。

- 新页面放在对应 `modules` 下，不要把模块业务放入公共目录。
- API 调用集中放在模块 `apis` 目录。
- 可复用状态放入 Pinia store，页面临时状态保留在组件中。
- 大型基础表使用服务端搜索和分页，禁止页面初始化全量加载。
- 关联坐标时使用批量查询，避免循环内查询数据库。
- PMTiles 文件不提交 Git；代码仓库只保存地图服务程序和说明。
- 接口返回继续使用统一 `Result` 格式。
- 修改数据库结构时同步更新 `db` 下 SQL 和本文档。

## 12. 常见问题

### MySQL：Public Key Retrieval is not allowed

本地 JDBC 地址需要包含：

```text
allowPublicKeyRetrieval=true
```

该选项适合本地开发。生产环境应配置 TLS 和更严格的认证方案。

### Spring Boot：Port 8081 was already in use

检查占用进程：

```powershell
Get-NetTCPConnection -LocalPort 8081 -State Listen
```

停止旧进程，或修改 `application.yml` 中的 `server.port`。

### 地图请求返回 206

这是 PMTiles 正常的字节区间响应。若地图空白，应继续检查浏览器控制台、Vite Worker 和地图样式，而不是把 206 当作错误。

### 缺少 maplibre-gl-worker.mjs

项目已在 `vite.config.js` 中排除 MapLibre 的依赖预构建，并使用 `vite --force`。停止旧的 Vite 进程后重新运行：

```powershell
npm run dev
```

再使用 `Ctrl+F5` 刷新浏览器。

### 地图服务未启动

确认 `8765` 正在监听，并检查两个 PMTiles 文件是否位于 `mapserver/data`：

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen
```

### 搜索框没有结果

依次检查：

1. Mapserver 是否运行在 `8765`。
2. `mapserver/data/geo.sqlite` 是否存在。
3. 浏览器 Network 中 `/api/*/search?keyword=` 是否返回 200。
4. 输入内容是否为空；空输入不会请求后端。

## 14. 地图与地理基础数据服务

旅行模块使用独立的 `mapserver` 提供离线地图和地理基础数据。机场、火车站、三级行政区不再存放于业务 MySQL，也不再由 Spring Boot 暴露搜索接口。

```text
Vue ────────────────> mapserver /api/*        搜索机场、车站、行政区
Vue ────────────────> mapserver /*.pmtiles    离线地图
Spring Boot ────────> mapserver /api/*        坐标补全、行政区校验与名称
Spring Boot ────────> MySQL                   用户业务数据
mapserver ──────────> data/geo.sqlite         地理基础数据
```

`mapserver/data/geo.sqlite` 包含：

- `airport`：机场代码、名称和坐标。
- `train_stations`：车站代码、名称和坐标。
- `sys_area`：省、市、区县三级行政区。
- `poi`：全国景点、博物馆、古迹、公园、宗教场所及主要自然景观，带 FTS5 和 RTree 索引。
- `region_boundary`：省、市、区县完整边界；通过 `region_boundary_rtree` 粗筛，再进行精确点面判断。

首次安装 Python 环境：

```powershell
cd mapserver
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

本地启动顺序：

```powershell
# 1. 地图与地理数据服务
cd mapserver
.\run.ps1

# 2. 在 IDEA 中启动 Spring Boot

# 3. 启动 Vue
cd vue-project
npm run dev
```

Spring Boot 通过 `mapserver.base-url` 配置服务地址，Vue 通过 `VITE_MAP_SERVER` 配置；两者默认均为 `http://127.0.0.1:8765`。

完成验证后，可执行 `db/migrations/drop_migrated_geo_tables.sql` 删除 MySQL 中保留的迁移前副本。
